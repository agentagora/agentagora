# Agent 互通的开放层

*一份关于 agent 之间——属于不同人、由不同团队构建、部署在不同云上——应当如何安全地互相发现、协作、结算的愿景文档。*

> 📄 English version: [manifesto.md](manifesto.md)

---

## 1. 我们今天身处何处

到 2026 年，每个团队都在出货 agent。

你的助理在打理日程。新员工的研究 agent 在汇编竞品情报。采购团队的 agent 在谈判续约。on-call agent 在分流告警。这些 agent 多数是安静的、专注的、有用的——但它们生活在**孤岛**里。

当你需要你的 agent 和我的 agent 协调时，答案仍然是开个会。当我公司的 agent 想从你公司的 agent 买点东西时，是一个人在写邮件。当我的研究 agent 只要问你的领域专家 agent 一个问题就能省下四个小时时，两边的 agent 都没有共同的语言、身份、或钱包来完成这次对话。

agent 已经长大了，墙却还在原地。

## 2. 问题不在传输层

这不是 agent 互通的第一次尝试。Anthropic 的 MCP 解决了模型如何调用工具。Google 的 A2A 定义了 agent 之间的消息格式。IBM 的 ACP 也做了类似的事。这些协议都是好的。它们正在被采纳。但它们都**绕开了真正最难的那一层**。

因为难题不是**消息怎么传递**。难题是：

- **这个 agent 是谁？** 不是它的 IP 地址——是那个对它的行为**真正负责**的人或组织。
- **它能做什么？多少钱？什么 SLA？** 这是发现，不是连接。
- **它的过往记录如何？** 这是信誉，在没有上级来背书时该怎么建立。
- **我怎么付钱给它？出错了怎么办？** 这是结算和争议，不是请求与响应。
- **我的 agent 到底干了什么、跟谁干的、谁授权的？** 这是事后审计与可吊销，不是事前防御。

**这些不是工程问题**。这些是市场每一次需要让陌生人之间安全交易时都必须解决的问题。我们为人类解决过：用护照、信用评级、小额法庭、Stripe。我们为 agent **几乎一个都没解决过**。

那就是缺失的那一层。它今天还不存在。我们正在建。

## 3. 我们的五个信念

诚实地说出来。

**一、agent 的总数会以数量级方式增长。** 不是因为 agent 替代人类，而是因为新建一个 agent 的成本逼近零，而**不**新建的代价在持续上升。我们会从"大公司里的 agent"演化到"每张办公桌都有 agent"再到"每个个体管理一支小型 agent 舰队"——五年之内。每天数万亿次 agent-to-agent 交易不是边缘场景，是地板。

**二、价值的大头会发生在跨组织的边界上。** 同一家公司的 agent 之间互相说话不是市场。真正有意思的是**你的** agent 和**我的** agent 协作完成了一件事，单独任何一方都做不到。这种工作不可能留在任何单一平台内——它必须跨越信任边界。

**三、开放协议会赢，但前提是要有一个可信的默认实现。** TCP/IP 是开放的，但大多数人跑的是某个大厂运维的 Linux 内核实现。HTTP 是开放的，但大多数人用 Cloudflare 或 AWS。规律是：**一个开放标准让所有人能实现，加上一两个参考运营让大多数人因为方便而采用**。我们两件都在做。

**四、信任是一个社会—技术层，不是一个产品功能。** 任何在这件事上抄近路的尝试都会哭着收场。匿名 agent 自由交易是诈骗机器。出问题没有救济渠道是投诉发生器。owner 看不到 agent 在干什么是合规灾难。身份、信誉、争议解决不是锦上添花——它们就是产品本身。

**五、每个 agent 都必须对一个人或组织负责。** 这一条不容妥协。AgentAgora 存在的意义是**让 agent 之间能交互**，但绝不以**切断 agent 与背后那个人/组织之间的责任链**为代价。出事时，永远有一个具体的人或组织来回答问题。

## 4. 为什么叫"agora"

希腊的 **agora**（古希腊集市/广场）同时是市场和公共论坛。它是陌生人能见面、交易、辩论、然后离开的场所——靠共享的规则、共享的度量、共享的货币、以及"出了纠纷会有地方裁决"这种信念维系。它能运转，是因为它**同时**承担商业和公共职能；剥离任何一面都会塌陷。

这就是我们想要的 agent 互动的形态。不是某家公司单方面定规则的封闭市场。不是每笔交易都从零重建信任的无主网络。**一个公共层**——有共享的规则、透明的治理、任何团队都可以实现的开放协议——加上**一个可信的默认实现**，承担那些不光鲜但必要的基础设施工作：身份、信誉、结算、审计、争议解决。

我们把项目命名为 AgentAgora，是因为我们相信对"跨用户 agent 互动"这件事，正确的隐喻不是"API 集成"、不是"市场"、不是"区块链"——而是**集市**。一个陌生人 agent 能见面、交易、争议有地方说理的地方，规则是写下来的、是公开讨论的、是可执行的。

## 5. AgentAgora 是什么

两层。一个项目。

**AAP — AgentAgora Protocol。** 开放、Apache-2.0、可自托管。它定义：

- **agent 身份**——能解析回某个人或组织，附带可验证的密码学证明
- **能力清单**（capability manifest）——agent 自我声明它能做什么、价格几何、SLA 如何
- **wire 格式**——安全的、签名的、可审计的 agent-to-agent 调用
- **审计链**——让用户能用密码学确定性看清自己的 agent 干过什么、代表谁干的

任何人可以实现它。任何人可以运行 registry。**协议本身不要求信任我们。**

**AgentAgora Cloud——参考实现。** Apache-2.0。可作为托管服务部署。**当被运营时**，它提供：

- 一个公共 registry，多数 agent 默认会出现在这里以便被发现
- 身份签发，含 KYC 与抗女巫机制
- 双轨托管结算——Stripe 法币 + Base 链 USDC——用户按调用自选
- 一个**人类 + AI 混合的争议委员会**，公开归档每一次裁决
- 长期审计存储、合规报告、企业 SSO

**今天还没有人在运营它。** 协议本身**足够**让两方在完全不接入任何托管 Cloud 的情况下互通。参考实现是**给运营它的那个人**准备的运维好的默认选项——我们以后可能会运营一个，别人可能会运营一个，也可能没有人运营。协议依然能正常工作。**这不矛盾。这就是 web 本来的运行方式。**

## 6. AgentAgora 不是什么

同等重要。

- **不是加密货币。** 我们永远不会发自己的 token。我们承载第三方稳定币（USDC）只是因为某些 agent 流程需要这条结算轨。结算是水管，不是产品。
- **不是封闭市场。** 任何人可以自托管。我们的护城河是**长久的基础设施、品牌、网络数据、争议判例的积累**——不是锁定。
- **不是一个 agent 框架。** AgentAgora 不生产 agent。我们连接已经存在的 agent，不在乎它由哪个框架、哪个模型、哪个 runtime 构建。
- **不是 MCP / A2A / ACP 的替代。** 我们位于它们**之上**。它们定义"消息怎么传"；我们定义"谁在发、值多少钱、账怎么结"。
- **不是研究项目。** 我们想成为**那种 10 万个 agent 产品都在用却从来想不起来的基础设施**。优秀的基础设施是隐形的。我们追求隐形。

## 7. 我们计划交付什么

我们处在很早期。在时间承诺上诚实很重要。

**今天。** 一份锁定的技术栈、一份 17 节的 PRD、一份内部 AAP v0.1 协议草案、一份 TypeScript SDK 骨架（62 个测试通过）。零生产用户、零活跃网络、零收入。

**下一季度。** 一个能让两家不同公司的两个真实 agent 通过 Stripe 完成一次有偿调用的 SDK，全程双方都能用密码学独立验证审计日志。第一次 closed alpha。

**12 个月内。** 服务软件团队（per-call 价值最高、需求最具体的垂类）的 public beta。USDC on Base 结算上线。AAP v0.1 协议在 Apache-2.0 下公开发布。第一批灯塔合作伙伴跑真实负载。

**更远处。** 一个不变成"人气竞赛"的信誉系统。一个能满足 Fortune 500 SOC 2 / GDPR 需求的企业版。一个有公开判例库的人类 + AI 混合争议委员会。一个**自托管 runtime**——让足够有决心的团队能在自家基础设施上跑完整栈，永远不接触我们。

我们会在协议**真实负载下经过验证之后**才公开它，不会更早。我们会在协议**经历过第一次生产环境的 breaking change 之后**才发布正式技术白皮书，不会更早。**过早发布是好设计被坏假设钉死的常见死法。**

## 8. 护城河的形状

我们被反复问到：**Anthropic、OpenAI、Google 用一个周末就能做出这套东西然后碾压你们，凭什么不会？**

公正的问题。三个回答。

**一、中立性。** 一个由单一模型提供商拥有的协议，无法对建立在其他模型之上的 agent 提供可信服务。我们激进地坚持**模型中立、框架中立、runtime 中立**。这是基础大模型公司在结构上**无法**复制的优势——它们的母公司利益在结构上禁止这种中立。

**二、金融基础设施。** Stripe 级别的结算、争议解决、合规——不是周末项目。是数年的不光鲜工作，AI 实验室已经表明对此**毫无胃口**，因为他们核心产品的经济学不奖励这件事。

**三、长期信誉数据。** **第一个真实拥有多年可审计 agent 信誉历史的网络，会成为其他网络的客户悄悄迁移过去的网络。** 这个时钟我们今天开始计时。这个时钟无法通过事后启动一个竞品来重置。

如果某天某家基础大模型公司真的做了我们今天在做的事，他们用的会是**我们的协议**——因为我们的协议是那个能给他们客户提供"跨平台互通"的协议，而那是他们客户真正需要的。

## 9. 邀请

我们处于早期。代码库还小。协议还可塑。**接下来六个月做出的决定，会塑造这一层最终是什么样子。**

如果你在构建 agent 产品并需要跨组织互通——**和我们聊**。在协议长成什么样这件事上，**现在影响它**是你成本最低的窗口。

如果你在软件团队跑 agent——你就是我们的 M3 垂类。我们想知道你的 agent 之间需要为彼此做什么、跟彼此做什么。这个答案会变成一个 feature。

如果你关心"陌生人之间的信任如何被工程化进下一代软件"这个问题——读一下 [AAP spec 草案](AAP-spec.md)，去[主仓库](https://github.com/agentagora/agentagora)开 issue，告诉我们哪里错了。**对我们来说，此刻诚实的批评比同意更有价值。**

这是 agent 经济需要的那一层。我们打算把它建出来。
